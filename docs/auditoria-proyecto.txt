AUDITORÍA TÉCNICA INTEGRAL — Panas Token Ecosystem (Ton‑telegram)
Fecha: $(date -u +%Y-%m-%dT%H:%M:%SZ)

1) Resumen Ejecutivo
- Estado: Monorepo esqueleto con múltiples utilidades y documentación, pero sin servicios implementados (backend/frontend/bots) aún.
- Riesgos críticos: exposición de secretos (PAT de GitHub y tokens de acceso) en código y en .env versionado; cifrado inseguro; referencias a scripts/servicios inexistentes.
- Priorización de remediación:
  1. Rotar y eliminar secretos expuestos (GitHub PAT, access tokens) y sacar .env del repo.
  2. Arreglar utilidades de cifrado (usar AES-GCM con createCipheriv/createDecipheriv e IV/tag correctos).
  3. Completar estructura modular con repos/submódulos o eliminar comandos que fallan.
  4. Añadir tests básicos y CI mínimo; revisar dependencias declaradas vs uso real.

3) Hallazgos de Seguridad (prioridad)
- P0 — Secreto GitHub PAT expuesto
  - Archivo: scripts/github-repos-fetcher.js
  - Detalle: define this.token con valor PAT real y lo imprime parcialmente al ejecutar.
  - Riesgo: acceso a repos privados, acciones en nombre de la cuenta, escalamiento.
  - Acción: REVOCAR/rotar inmediatamente el PAT en GitHub; eliminar del repo; usar solo GITHUB_TOKEN desde entorno/secrets.

- P0 — Archivo .env versionado con secretos
  - Archivo: .env
  - Detalle: contiene DR_TAPIA_ACCESS_TOKEN real y múltiples credenciales/config sensibles.
  - Riesgo: exfiltración de tokens; uso malicioso.
  - Acción: eliminar .env del control de versiones; añadir a .gitignore; rotar/invalidar cualquier token clave.

- P0 — Cifrado inseguro en scripts/secure-encrypt.js
  - Uso de crypto.createCipher y createDecipher (deprecated) sin IV pasado; se genera iv pero NO se utiliza; GCM requiere createCipheriv/createDecipheriv con IV y tag.
  - setAAD y setAuthTag usados, pero sin asociar el IV; el esquema actual puede fallar o dar falsa sensación de seguridad.
  - Acción: reescribir con crypto.createCipheriv('aes-256-gcm', key, iv); almacenar {ciphertext, iv, tag}; y simétricamente al descifrar.

- P1 — Token/Access data incrustados en wallet-manager
  - Archivo: scripts/wallet-manager.js
  - Detalle: accessToken largo en claro; URLs y listas de direcciones en claro (estas últimas pueden ser públicas, pero el token no).
  - Acción: mover todo token a variables de entorno o a un gestor de secretos; si se requiere persistencia, usar secure-encrypt (una vez corregido).

- P1 — Fugas accidentales en logs
  - Archivo: scripts/github-repos-fetcher.js
  - Detalle: imprime prefijo del token en consola (“Usando token: xxxxxxxx…”).
  - Acción: no loggear ningún fragmento de credenciales.

- P2 — Falta de validación de inputs / rate limiting en utilidades CLI
  - Scripts CLI reciben parámetros y tocan red/sistema; carecen de validaciones robustas.
  - Acción: validar argumentos, añadir safe defaults y manejo de errores uniforme.
